# Text engine

## Encoding (verified: tbl/jp.tbl decodes the opening event and the on-screen fairy line "実は今回、初仕事なんですけど、")

16-bit little-endian codes = font cell index; `tbl/jp.tbl` keys are the two bytes low-first (`2400=あ` is 0x0024).
Generated by `tools/mktbl.py` (layout below + `tools/fontmatch.py`), then a hand-edited source.

| Codes | Content |
|---|---|
| 0x000 | blank (full-width space) |
| 0x001-0x014 | 、。・：？！々ー～“”（）｛｝「」『』－ (set A; decoded as stand-ins ､｡･:?!〻ｰ~"'()〔〕｢｣《》-) |
| 0x015 | ＄ ; 0x016-0x01F ０-９ ; 0x020-0x022 Ｋ Ｏ Ｘ |
| 0x023-0x071 | hiragana ぁ-ん without ぢ ゎ ゐ ゑ |
| 0x072-0x0BD | katakana ァ-ン without ヂ ヅ ヌ ユ ヲ ヮ ヰ ヱ, then ヴ |
| 0x0BE-0x56D | kanji (JIS level 1, used-only, Shift-JIS order); 0x56E-0x57A level-2 kanji 凛..騙 |
| 0x57B-0x5AD | ，．Ａ-Ｚ (no Ｋ Ｏ Ｘ) ａ-ｚ |
| 0x5AE-0x5B4 | ぢ ヌ ユ ヲ ヂ ヅ ② (added later, out of order) ; 0x5B5-0x5BE kanji ; 0x5BF ③ ; 0x5C0-0x5CB kanji ; 0x5CC ④ |
| 0x5CD-0x5E0 | 、。・：？！々ー～“”（）｛｝「」『』－ (set B, the main dialogue set; glyphs equal set A except 、・ shifted 1 px) |
| 0x5E1-0x5E8 | 北氷峡岩礁河湾 ￥ ; 0x5E9 blank cell used as a space (decoded 〿) |
| 0x5EA-0x66B | second kanji block, Shift-JIS order (史..逞) ; 0x66C-0x66F blank ; 0x670+ is not font |

Both punctuation sets occur in dialogue (set B ~950 uses, set A ~200 in PSX.EXE strings), so the table gives set A
distinct stand-ins to keep `encode(decode())` byte-exact.

Control codes (verified: text printer 0x800FC270, `lhu` of the code at text_ptr + 2*index, compare chain):

| Code | Args (halfwords) | tbl | Meaning |
|---|---|---|---|
| 0xFFFF | 0 | `{end}` | end of message |
| 0xFFFE | 0 | `{n}` | newline (+0x16 line++, +0x14 column=0) |
| 0xFFFC | 0 | `{wait}` | wait for button, next page |
| 0xFF00 | 1 | `{ff00:XXXX}` | stores the arg at obj+0x1E (used by the glyph call: colour or font page, guess) |
| 0xFF10 | 1 | `{speed:XXXX}` | stores the arg at obj+0xE (print delay) |
| 0xFF90 | 2 | `{num:AAAABBBB}` | reads the low bytes a, b, calls 0x800FDE28(a*10+b): face/expression change (strings start with it before a speaker's line, guess) |
| other 0xFFxx | 0 | `{fffd}` `{fffb}` | skipped by the printer (the event VM at ~0x800CA500 compares FFFD/FFFB) |

Text object: `*(0x8001A4B8)`; +0 u32 text pointer, +4 u16 index, +8 u8 window id, +0xC/+0xE delay, +0x14 column,
+0x16 line, +0x26 end flag, +0x28 wait flag, +0x2C max columns. The printer calls draw-glyph 0x800FC97C.

## Script location (verified: PSX.EXE strings by scan + roundtrip test; event scripts by the on-screen line)

- **PSX.EXE** holds ~970 strings / 28 KB (`python -X utf8 tools/scantext.py work/disc/tree/PSX.EXE --regions`):
  0x155F3C-0x15CAB0 (place names, items, skills, fairy/tutorial dialogue, opening event; the opening and the fairy
  introductions are stored twice, 0x15A858-0x15B950 and 0x15B9B4-0x15CAB0, one copy per gender of the angel, guess
  from "天使様も、新人みたいだし、女同士で"), 0x164E7A-0x16667E (menus, system messages, skill names), plus scattered
  short strings. Strings are FFFF-terminated and padded to 4 bytes with 0x0000; many sit inside records (a pointer
  points 10/14/18 bytes before the text) and 405 are pointed at directly by a u32 vaddr. Pointer table example:
  0x15C800 lists 0x8016A668.. for the opening event.
- PSX.EXE 0x15CDA2-0x163E0A (RAM 0x8016C5A2-0x8017360A) is 28 KB of zeros: the event-script load buffer
  (`events.md`), not free space.
- The opening event text is copied to RAM 0x80180CF0 before printing (the line buffer the printer reads).
- **The bulk of the dialogue is in 468 event-script files in GDATA.BIN** (~550K characters, inline in VM bytecode,
  not FFFF-terminated): `events.md`. A scan for FFFF-terminated strings misses them, which is why the first passes
  found "no script" in GDATA.
- Other EXEs (FD_BALL, GOVER, PS_MOV, EPILOG, FIN, FD_MOV): 6-31 short strings each; SDATA.BIN: a few false hits.
  No Shift-JIS sentences anywhere except the credits. XAPACK1.XA (335 MB of XA audio) holds no text.

## Credits (verified: decoded the cast list)

DATA/STAFF.TXT: Shift-JIS with each byte of a double-byte character +1 (0x82 0x41 = 0x81 0x40 "　"); line break
0x0E 0x0B; `$` lines are separators/pauses (guess). Read by DATA/FIN.EXE (font 01-13.TIM + FONTCLUT.TIM).

## Font (verified: traced the glyph writer)

12x12 1bpp, one image 192 px wide (16 cells per row), 24 bytes per row, bit 0 = leftmost pixel. Code c -> cell
(c & 15, c >> 4). RAM 0x80130BC0 = PSX.EXE 0x1213C0; 0x66C cells = 29.6 KB, ending at PSX.EXE 0x128A40. The glyphs
are MS Gothic's 12 px embedded bitmap (kanji match exactly), kana/Latin/punctuation are the game's own.
- 0x800FC97C draw-glyph: calls 0x800FDCA8(font=0x80130BC0, code, buf) which reads 12x12 pixels through 0x800FDDF0
  (bit fetch) into a 2bpp buffer, then expands to 4bpp halfwords into the line buffer.
- Line buffer: RAM 0x8017C320, 120 bytes (240 px 4bpp) per pixel row; writers 0x800FD81C (clear), 0x800FCB24 (glyph).
  Uploaded to VRAM ~(960,256) as a 4bpp texture (values 0/1). Found with `watch.lua` write mode from
  `work/qa/ng/s007500.sstate`.
- Box: 3 lines of up to ~19 full-width glyphs (the fairy box: "お互い新人みたいだし、" + room); 240 px line buffer.

English plan (phase 5): the cell is 12 px; a half-width or VWF font drawn through the same 1bpp image path is the
obvious route (widths per glyph in a new table; the glyph writer already takes a per-call width in $s0).
