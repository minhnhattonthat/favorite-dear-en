# Text engine

## Encoding (verified: tbl/jp.tbl decodes the opening event and the on-screen fairy line "実は今回、初仕事なんですけど、")

16-bit little-endian codes = font cell index; `tbl/jp.tbl` keys are the two bytes low-first (`2400=あ` is 0x0024).
Generated by `tools/mktbl.py` (layout below + `tools/fontmatch.py`), then a hand-edited source.

| Codes | Content |
|---|---|
| 0x000 | blank (full-width space) |
| 0x001-0x014 | 、。・：？！々ー～“”（）｛｝「」『』－ (set A; decoded as stand-ins ､｡･:?!〻ｰ~"'()〔〕｢｣《》-) |
| 0x015 | ＄ ; 0x016-0x01F ０-９ ; 0x020-0x022 Ｋ Ｏ Ｘ |
| 0x023-0x071 | hiragana ぁ-ん without ぢ ゎ ゐ ゑ |
| 0x072-0x0BD | katakana ァ-ン without ヂ ヅ ヌ ユ ヲ ヮ ヰ ヱ, then ヴ |
| 0x0BE-0x56D | kanji (JIS level 1, used-only, Shift-JIS order); 0x56E-0x57A level-2 kanji 凛..騙 |
| 0x57B-0x5AD | ，．Ａ-Ｚ (no Ｋ Ｏ Ｘ) ａ-ｚ |
| 0x5AE-0x5B4 | ぢ ヌ ユ ヲ ヂ ヅ ② (added later, out of order) ; 0x5B5-0x5BE kanji ; 0x5BF ③ ; 0x5C0-0x5CB kanji ; 0x5CC ④ |
| 0x5CD-0x5E0 | 、。・：？！々ー～“”（）｛｝「」『』－ (set B, the main dialogue set; glyphs equal set A except 、・ shifted 1 px) |
| 0x5E1-0x5E8 | 北氷峡岩礁河湾 ￥ ; 0x5E9 blank cell used as a space (decoded 〿) |
| 0x5EA-0x66B | second kanji block, Shift-JIS order (史..逞) ; 0x66C-0x66F blank ; 0x670+ is not font |

Both punctuation sets occur in dialogue (set B ~950 uses, set A ~200 in PSX.EXE strings), so the table gives set A
distinct stand-ins to keep `encode(decode())` byte-exact.

Control codes (verified: text printer 0x800FC270, `lhu` of the code at text_ptr + 2*index, compare chain):

| Code | Args (halfwords) | tbl | Meaning |
|---|---|---|---|
| 0xFFFF | 0 | `{end}` | end of message |
| 0xFFFE | 0 | `{n}` | newline (+0x16 line++, +0x14 column=0) |
| 0xFFFC | 0 | `{wait}` | wait for button, next page |
| 0xFF00 | 1 | `{ff00:XXXX}` | stores the arg at obj+0x1E (used by the glyph call: colour or font page, guess) |
| 0xFF10 | 1 | `{speed:XXXX}` | stores the arg at obj+0xE (print delay) |
| 0xFF90 | 2 | `{num:AAAABBBB}` | reads the low bytes a, b, calls 0x800FDE28(a*10+b): face/expression change (strings start with it before a speaker's line, guess) |
| other 0xFFxx | 0 | `{fffd}` `{fffb}` | skipped by the printer (the event VM at ~0x800CA500 compares FFFD/FFFB) |
| 0xFF20 | 1 | `{var:XXXX}` | template placeholder for a name (arg 0x0F the hero, 0x0E ...); not the printer's, a formatter fills it (verified: tokenising the regions with it leaves no gaps) |
| 0xFFE0 | 2 | `{val:XXXXXXXX}` | template placeholder for a number (`FFE0 0000 0001`, "the level became N") |

Event scripts use a different printer with its own codes (`events.md`, `tbl/ev.tbl`).

PSX.EXE strings that end 2 bytes off a 4-byte boundary are followed by one 0x0000 pad (verified: 347 pointers land
right after it). Name-entry character grids at 0x17DA4 and 0x17E64 use 0xFFFF as an empty cell. Inside the two text
regions the only non-text is `extract.EXE_DATA` (u32 pointer tables 0x156818, 0x159F78, 0x15C7D8; layout records and
a palette 0x1656D6-0x1660E0). Shift-JIS appears only as memory-card titles (PSX.EXE 0x1D770 "フェイバリットディア
ゲームデータ", EPILOG.EXE 0x48330 "...クリアデータ", and a test-build title in FD_BALL/PS_MOV/EPILOG 0x11A4) and the
credits.

## Extraction (phase 4, `tools/extract.py`, gate `tests/test_extract.py`)

`script/events/<sector>.tsv`, `script/exe.tsv`, `script/staff.tsv`, `script/sjis.tsv`; columns id, jp, en, notes;
ids are original addresses (`<sector>.<file byte offset>`, `PSX.<offset>`, `STAFF.<line>`). Every row round-trips
byte-exact; coverage is tested per source. The small EXEs (FD_BALL, GOVER, PS_MOV, EPILOG, FIN, FD_MOV, _LOADE,
SLPS_01.759) hold no game text in this encoding: their scan hits are code and font-map tables.

Text object: `*(0x8001A4B8)`; +0 u32 text pointer, +4 u16 index, +8 u8 window id, +0xC/+0xE delay, +0x14 column,
+0x16 line, +0x26 end flag, +0x28 wait flag, +0x2C max columns. The printer calls draw-glyph 0x800FC97C.

## Script location (verified: PSX.EXE strings by scan + roundtrip test; event scripts by the on-screen line)

- **PSX.EXE** holds ~970 strings / 28 KB (`python -X utf8 tools/scantext.py work/disc/tree/PSX.EXE --regions`):
  0x155F3C-0x15CAB0 (place names, items, skills, fairy/tutorial dialogue, opening event; the opening and the fairy
  introductions are stored twice, 0x15A858-0x15B950 and 0x15B9B4-0x15CAB0, one copy per gender of the angel, guess
  from "天使様も、新人みたいだし、女同士で"), 0x164E7A-0x16667E (menus, system messages, skill names), plus scattered
  short strings. Strings are FFFF-terminated and padded to 4 bytes with 0x0000; many sit inside records (a pointer
  points 10/14/18 bytes before the text) and 405 are pointed at directly by a u32 vaddr. Pointer table example:
  0x15C800 lists 0x8016A668.. for the opening event.
- PSX.EXE 0x15CDA2-0x163E0A (RAM 0x8016C5A2-0x8017360A) is 28 KB of zeros: the event-script load buffer
  (`events.md`), not free space.
- The opening event text is copied to RAM 0x80180CF0 before printing (the line buffer the printer reads).
- **The bulk of the dialogue is in 468 event-script files in GDATA.BIN** (~550K characters, inline in VM bytecode,
  not FFFF-terminated): `events.md`. A scan for FFFF-terminated strings misses them, which is why the first passes
  found "no script" in GDATA.
- Other EXEs (FD_BALL, GOVER, PS_MOV, EPILOG, FIN, FD_MOV): scan hits only, no game text (phase 4 check); SDATA.BIN:
  a few false hits. No Shift-JIS sentences anywhere except the credits and memory-card titles. XAPACK1.XA (335 MB of
  XA audio) holds no text.

## Credits (verified: decoded the cast list)

DATA/STAFF.TXT: Shift-JIS with each byte of a double-byte character +1 (0x82 0x41 = 0x81 0x40 "　"); line break
0x0E 0x0B; `$` lines are separators/pauses (guess). Read by DATA/FIN.EXE (01-13.TIM are the pictures; FONTCLUT.TIM
is an empty 256x256 image).
- FIN's font is inside FIN.EXE: a full Shift-JIS 12-px font, 22 bytes per glyph (11 rows, u16 big-endian, bit 15 =
  leftmost pixel; e.g. FIN file 0x16984). 0x80013BD0 `glyph_addr(char *sjis)` = base (0x8002365C for codes
  0x8140-0x84BE, 0x80026364 for kanji) + 22 * index, index from 0x80013C5C (SJIS -> index, the BIOS-style table at
  0x800235DC). 0x80013940 renders the glyph with a shadow (`v | v>>1 | v>>2`) into a buffer; the caller is 0x800134CC.
- Single-byte ASCII in a line hangs the roll (tested); full-width Latin (ＡＢＣ, ａｂｃ, ０-９, ［］) renders. So the credits
  are English in full-width forms (`insert.fullwidth`, 14 letters per line at x=150). The leading `&` of the closing
  cards (STAFF.457-460) is a single-byte code and stays.
- Pair glyphs (done, phase 8): `asm/fin.asm` hooks `glyph_addr`. FIN's lead-byte test (0x80011F1C, on the decoded
  text) takes 0x81-0x9F and 0xE0-0xFC; its font ends at 0x9872, so leads 0xE0-0xFC carry two letters:
  n = (lead-0xE0)*189 + (trail-0x40), letters `FIN_CHARSET[n/74]`, `[n%74]` (`font_en.fin_pairs`). Code, font
  (11 bytes per letter, rows 1-11 of en6x12) and scratch sit over the Cyrillic + box-drawing glyphs (indexes
  426-523 of table A: 0x80025AF8-0x80026364; table A is linear over the 524 defined codes 0x8140-0x84BE). Each
  character is its own sprite (0x800134CC, 256 slots of 44 bytes at 0x80050190, 16x16 4bpp texture), advance 12 px
  (0x800113E4), so a pair code halves the sprite count. The shadow is dark on black and does not show; 5-px letters
  read cleanly. 28 letters from x=148.
- Line codes (0x80011208..): a leading `%` (0x25) starts the line at x=64 instead of 0x94=148 (arg of 0x80012278);
  `&` the closing cards; `#`, `\` other modes (not traced). `%` is unused by the original file, and for good
  reason: a `%` line stops the roll for good (tested phase 8: with the painter rows as `%A   B` the text after
  "Backgrounds" never appears and the roll never ends; the same build without `%` runs to the end). The two-name
  painter rows are now one name per line (`|` in `trans/staff/en.tsv`, `insert.staff_en`).

## Font (verified: traced the glyph writer)

12x12 1bpp, one image 192 px wide (16 cells per row), 24 bytes per row, bit 0 = leftmost pixel. Code c -> cell
(c & 15, c >> 4). RAM 0x80130BC0 = PSX.EXE 0x1213C0; 0x66C cells = 29.6 KB, ending at PSX.EXE 0x128A40. The glyphs
are MS Gothic's 12 px embedded bitmap (kanji match exactly), kana/Latin/punctuation are the game's own.
- 0x800FC97C draw-glyph: calls 0x800FDCA8(font=0x80130BC0, code, buf) which reads 12x12 pixels through 0x800FDDF0
  (bit fetch) into a 2bpp buffer, then expands to 4bpp halfwords into the line buffer.
- Line buffer: RAM 0x8017C320, 120 bytes (240 px 4bpp) per pixel row; writers 0x800FD81C (clear), 0x800FCB24 (glyph).
  Uploaded to VRAM ~(960,256) as a 4bpp texture (values 0/1). Found with `watch.lua` write mode from
  `work/qa/ng/s007500.sstate`.
- Box: 3 lines of up to ~19 full-width glyphs (the fairy box: "お互い新人みたいだし、" + room); 240 px line buffer.

## English (phase 5, verified in the marker build)

- **Why not VWF:** the event printer places each glyph on its own: 0x800CE248(column, line, ..., code) uploads one
  12x12 4bpp image to VRAM x = 0x3C0 (or 0x280) + 3*column halfwords, y = 0x100 + 12*line, through 0x800FD3A0. Pixel
  positions are 4-px steps and nothing composes a line, so a VWF would mean rewriting the printer.
- **Pair glyphs:** a halfword 0x2020-0xFEFF is two letters (low byte left, high byte right, bytes 0x20-0x84 of
  `fonts/en6x12.txt`). `asm/font.asm` hooks 0x800FDCA8 (render font cell `code` from the 1bpp image, 24-byte rows):
  for a pair it ORs both 6x12 glyphs into cell 0 of a 288-byte scratch image and renders that. Every path that draws
  with this font goes through it. Codes below 0x2000 render the Japanese font as before.
- So a line holds 2x the Japanese glyph count in letters, text costs 1 byte per letter (the same density as
  Japanese per halfword), and the engine's column/line/page logic is untouched. `tools/en.py` encodes; an odd letter
  before a control code is padded with a space.
- Hook, font (1212 bytes) and scratch live at 0x80124E60 (the free run in `space.md`, under 0x80125AF0, checked by
  armips). The hook body is `asm/pair.inc` + `asm/pair_data.inc`, shared with EPILOG.
- **EPILOG.EXE** (endings) has its own copy of the renderer at 0x800526E8 (same interface: row = code >> 4, column =
  code & 15, 24-byte rows), reached via 0x800311DC -> 0x80051C98. `asm/epilog.asm` hooks it (displaced
  `addiu sp,-0x40` / `sw ra,0x3c(sp)`); the blob lives at 0x80170000 (`space.md` §EPILOG). Verified: ending 3 shows
  clean English, 40 letters x 3 lines (`docs/windows.tsv`).
- **Glyph torture line** (`build.py --torture`: every font glyph plus double and triple spaces as each event row's
  first three lines): all 101 glyphs distinct and clean, spaces keep their width (`work/qa/p5/torture/sheet.png`).
- **FIN.EXE (credits)**: see §Credits below.
- **Not yet handled:** a runtime-inserted name of odd length (the angel's name, entered on the grid) leaves a half-cell
  gap after it in dialogue.

## Name entry (phase 8, `asm/name.inc`)

- Code 0x80104A00-0x80106B40. Grid table 0x800275A4 (file 0x17DA4): three pages of 7 rows x 16 halfword cells,
  page 2 = Latin 0x800275A4, page 0 = katakana 0x80027684, page 1 = hiragana 0x80027764; 0xFFFF = no cell; row 6 =
  buttons (cols 0-3, 4-7, 8-11 = the pages, 12+ = END). Page var 0x8002752E, count 0x8002752C, cursor x/y bytes
  0x80027504/5. Each page is drawn into VRAM (v = 0x100 + 72 * page + 12 * row) by 0x80105844 / 0x801059E4 /
  0x8010567C; the on-screen name is one sprite per cell copied from that image (u, v kept in a parallel array), 16 px
  apart (0x801069B0) over underline marks (0x80106A60).
- Init 0x80104E24 (runs when the grid opens) loads the default name ラビエル (0x80175B34) with the cursor on END; then
  0x800C0F58 draws the katakana page and sets page 0. On END + YES, 0x801054D4 copies the codes to the save's name
  0x8001F5F6 (8 halfwords, 0xFFFF-filled first).
- English: Latin cells are "A " pair codes; the Latin page opens first with "Raviel"; 10 cells, 8 px apart (buffers
  moved to 0x80125980+); on commit single letters are packed two per halfword, capped at 5 halfwords. Verified
  (`tools/lua/peek.lua`): default -> 0x8001F5F6 = `Ra vi el FFFF`, week screen shows "Raviel" (`warp.py week1`);
  `warp.py newgame_name10` -> `Ra vi ww ww ww FFFF`, an 11th letter refused.
