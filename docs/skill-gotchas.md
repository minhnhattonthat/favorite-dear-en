# Skill gotchas (one line each: reference file, then the fact)

- SKILL.md Step 0: in an Orca profile (CLAUDE_CONFIG_DIR elsewhere) the plugin's guard hook never loads; the canary went through until the hooks block was added to .claude/settings.json with the stable marketplace path (it then took effect without a restart).
- SKILL.md / platform-ps1.md: a repo helper named `tools/re.py` shadows the stdlib `re` (capstone imports fail); name it `retools.py`.
- emulator-qa.md (PCSX-Redux): `L.dump_ppu` writes 2 MB, not 1 MB: the first 1 MB is VRAM 1024x512 16-bit, the rest is padding/second copy.
- emulator-qa.md (PCSX-Redux): read breakpoints on script text in RAM never fired for this game while write breakpoints (watch.lua, --debugger) did; trace the draw path from the output buffer backwards.
- platform-ps1.md: emu.py `L.shot(name)` on PCSX writes a file without .png extension (`dump_7650`), and it is a raw-size file the Read tool rejects; use --shots instead.
- pipeline.md §Recon: a scan for FFFF-terminated strings found only 28 KB of text and the dialogue looked missing; the real script was inline in VM bytecode (no terminator, opcode-delimited). Search RAM for an on-screen line encoded with the table before concluding text is compressed.
- pipeline.md §Recon (code = font cell): kana read by eye from a sheet misread 々 as ゞ; decode a long script sample and read it as Japanese (数々の) before trusting the table.
- platform-ps1.md: the font image had 0x66C cells, not the 0x5E0 an earlier session assumed; find the font end by matching every cell (scores collapse on non-font data) rather than by eye.
- context-mode (Claude Code plugin): Bash output above ~4 KB comes back as a stub; keep disassembly/sample prints under that or use ctx_execute.
- emulator-qa.md §Hooks (scripts/sheet.py): `--crop` past the image edge crashes with struct.error in write_png; PS1 shots switch between 320 and 640 wide per screen, so check the size first.
- translation.md / ground rules (Claude Code Edit tool): an Edit whose old/new string ends in a tab dropped that tab and merged two TSV columns; rewrite small TSVs whole.
- emulator-qa.md §Debug tool (PS1): a game that loads event scripts by name from a name table in RAM can be warped by overwriting the name slot of the first event the game loads; no debugger and no code patch needed (Favorite Dear, docs/re/debug.md).
- emulator-qa.md §Debug tool (PS1, PCSX-Redux): `PCSX.getRegisters()` is writable from `L.on_frame` (`r.GPR.n.a0 = x; r.pc = fn`); jumping into a never-returning routine (an exec of another program) from the game's vsync wait loop works as a warp. Calling a routine that returns (a battle start) the same way hung the emulator: no frame after the call.
- context-mode (Claude Code): Read/Bash outputs over ~4 KB come back as a one-line stub even for 70-line files; read with offset/limit in ~35-line parts or print only the answer from ctx_execute.
- emulator-qa.md §Debug tool / platform-ps1.md (PCSX-Redux): `PCSX.getScratchPtr()` gives the 1 KB scratchpad (0x1F800000) as a writable byte array, like getMemPtr; programs that pass parameters to the next EXE through the scratchpad (endings here) can be warped by writing it before the exec jump.
- pipeline.md §Extract / tbl.py: Claude Code's Edit tool strips trailing whitespace from the lines it rewrites, full-width U+3000 included, so an edit whose old/new string spans `0000=　` leaves `0000=` and Table.load fails; keep .tbl edits clear of space-valued lines (or write them as `\s`).
- pipeline.md §Extract (PS1 event VMs): a per-file opcode argument-count table in the script header (here u16 at +6, read by the step loop as `pc += 1 + tab[op]`) makes a linear sweep exact; look for it before decoding each handler by hand.
- emulator-qa.md §Debug tool (PS1): when a game copies a lookup table into RAM late (here the battle stage table, reset when the host event loads), a one-time RAM patch silently does nothing; rewrite the entry every frame until arrival and log when it had to.
- scripts/sheet.py: a `--crop` box that runs past the image (y 320 on a 640x240 PCSX shot) dies with `struct.error: 'I' format requires 0 <= number` from write_png instead of a clear message; check the shot size first (PCSX shots are 640x240 or 320x240).
- scripts/jp_left.py (PS1, 16-bit tables written low byte first like `2400=あ`): pass `--tbl` without `--le16`; GDATA-sized files scan fine, and every PS1 EXE shows the same SDK table runs (沈親替手捜…) as false positives.
- pipeline.md §Extract (event VMs): a linear opcode sweep can be self-consistent and still wrong: a message whose first glyph is below the opcode count parses as an op. Check every show-message reference lands on a message; here it hid 1300+ battle lines and some world-news text.
- pipeline.md §Marker: an in-place EXE marker cut by bytes (`new[:len-2] + FFFF`) drops the row's trailing `{wait}{end}` and hung the opening; trim letters, keep codes. A "text region" bound guessed from the first string can start inside a data table (here the event-name table's tail): the marker wrote into it and the next name lookup strcpy'd over all RAM.
- emulator-qa.md §Free space: PS1 sub-programs exec'd from the main EXE (ending, credits) have their own copies of the renderer at other addresses and need their own hook and free RAM; a trap-byte fill (Lua, after the exec) found the image's zero runs live there.
- platform-ps1.md (armips): `.include` resolves from the process cwd, not the including file's folder (run armips with cwd = the asm dir); symbol names are case-insensitive, so a label `stub` collides with `STUB equ` ("Parse error '0x8009F800'"); a `.macro` holding `.incbin FONT_BIN` failed ("Invalid immediate expression"): use a second include file. Appending a code sector to a PS-X EXE: bump t_size, point pc0 at a stub that copies the blob to free RAM, calls BIOS A(44h) FlushCache and jumps to the old pc0.
- platform-ps1.md (credits): a sub-program can draw only double-byte Shift-JIS (FIN.EXE here hangs on ASCII bytes); full-width Latin is a zero-engine-work English path, at half the density of pair glyphs.
- emulator-qa.md §Debug tool: warp scenes with AFTER=hold stop at PROOF+60, so a long sequence (a staff roll) never shows its text; override with `--var "AFTER='idle'"` (any value but mash/hold runs to the frame limit) and pick the proof frame from the original.
docs/re/graphics.md (this repo): GDATA e009 small labels (信頼度 信仰心 ...) are NOT what the hi-res status screens (hub_ability2/3) draw; find the real source by VRAM dump before redrawing.
references/platform-ps1.md: a leading % in FIN.EXE STAFF.TXT (x=64 line mode) freezes the credits roll; check a new line code over the whole roll, not one page.
